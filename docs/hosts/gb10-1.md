# gb10-1

The first GB10 workstation's host descriptor, read by the hosting-upgrades skill
(`.claude/skills/hosting-upgrades/`). It records only what the skill needs to reach the host and
judge what it finds there; every other fact (its hardware, OS, kernel, engines, served and stored
models) comes from the probe a run takes. gb10-2 has no descriptor: it is reserved for
spike-ai-pipeline.

## SSH short name

`gb10-1`

## Purposes

The purposes the host serves today, each with its load target: the concurrent sessions or
requests it is sized for, and the context each reaches. Today the host serves model set A, as its
screen record's end state reads it back (`docs/screens/gb10-1/2026-11-05.md`, "End state"), from
the shared preset, spike-model-engines `host/llama-preset/models.ini`, whose sections give each
target. The figures below are main's at 933ec0f (read 2026-11-06), whose set A sections match the
screen branch's at 4d5e114 that the end state read (main drops only the unserved Gemma agent
section). Which purposes this host serves, and at what load, is spike-model-layout's to decide; a
change there changes this list.

- **agent**: the main chat and tool-calling model the consumers' agent sessions run on. Load
  target: 4 concurrent sessions sharing one 131,072-token context pool (a unified KV cache), so
  one session reaches up to 131,072 tokens and each of four full sessions 32,768. From the
  `gpt-oss-120b-MXFP4-set-a` section: `c = 131072`, `parallel = 4`, `kv-unified = true`.
- **vision**: image input beside text. Load target: 4 concurrent requests of 8,192 tokens each.
  From the `google/gemma-4-26B-A4B-it-qat-q4_0-gguf:Q4_0` section: `c = 32768`, `parallel = 4`,
  split evenly across the slots (the preset's comment on its Gemma 4 sections).
- **audio**: speech and audio input beside text. Load target: 4 concurrent requests of 8,192
  tokens each. From the `ggml-org/gemma-4-E4B-it-GGUF:Q8_0` section: `c = 32768`,
  `parallel = 4`, split the same way.
- **embedding**: text embeddings for retrieval. Load target: 16 concurrent requests of 8,192
  tokens each. From the `mrutkows/granite-embedding-english-r2-GGUF:BF16` section:
  `c = 131072`, `parallel = 16`.

## Watch items

Named things every run checks, beside its own scan.

- vLLM NVFP4 decode speed on SM121
- EmbeddingGemma 2 serving on SM121
- llama.cpp concurrent-session throughput
- llama.cpp gpt-oss template errors on tool schemas
  ([#30781](https://github.com/ggml-org/llama.cpp/issues/30781))
- llama.cpp prompt-cache cross-conversation restore under concurrency
  ([#27148](https://github.com/ggml-org/llama.cpp/issues/27148), fix
  [#27624](https://github.com/ggml-org/llama.cpp/pull/27624))
- llama.cpp unified-KV multi-sequence attention on CUDA
  ([#29510](https://github.com/ggml-org/llama.cpp/pull/29510))
- GB10 reboot and reset reports on the running NVIDIA kernel
  ([NVIDIA forum 387397](https://forums.developer.nvidia.com/t/dgx-spark-repeatedly-rebooting-after-most-recent-update/387397))
- Display reserved memory (UEFI) on the Dell GB10
- Google renaming its QAT GGUFs, or llama.cpp accepting `_` before an `-hf` tag, either of which
  lets this host move past b12098
  ([#31620](https://github.com/ggml-org/llama.cpp/pull/31620),
  [#31639](https://github.com/ggml-org/llama.cpp/pull/31639))
