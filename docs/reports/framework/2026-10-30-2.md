**1. Boot-order check: `llama` flagged.**
- **What the probe shows:** it publishes `8080/tcp tailnet4` from configured binds
  `8080/tcp tailnet4`, while `net.ipv4.ip_nonlocal_bind` is 0 (`probe == engines ==`,
  `== container-runtime ==`).
- **The risk:** on a boot where docker starts before Tailscale has assigned the tailnet IPv4
  address, the router comes up healthy with no published port, and serves nothing off the host.
- **The remedy,** a root step for the architect to run on framework:

  ```sh
  echo 'net.ipv4.ip_nonlocal_bind = 1' | sudo tee /etc/sysctl.d/60-tailnet-bind.conf
  sudo sysctl --system
  ```

- **Its side effect:** any process on the host may then bind an IPv4 address the host doesn't hold
  yet.
- **Its rollback,** also root: `sudo rm /etc/sysctl.d/60-tailnet-bind.conf`, then
  `sudo sysctl -w net.ipv4.ip_nonlocal_bind=0`, or a reboot. `sysctl --system` alone would leave
  the value at 1.
- **Not flagged:**
  - `vllm` is stopped, and a stopped container publishes nothing.
  - No container binds `tailnet6`.
- **Verdict:** hold, unchanged from the morning report.
